# General review and WinGet preparation — 2026-11-05

This first section records the initial conservative review. The later authorized
runtime migration and publication are recorded at the end of this document.

Baseline: **0.1.17**, commit `0dfb64b`. The user reports that the app currently
works correctly. This review found no demonstrated defect requiring a change
to the mouse, keyboard, clipboard, connection or application lifecycle code.
No files under `MouseWithOutBorders/` were changed, and the version remains
0.1.17. The installed application was not stopped, replaced or reconfigured.

## Scope and results

Static review covered authenticated transport, bounded frames and queues,
handoff ownership, input recovery, clipboard encryption and path validation,
local key remapping, single-instance activation, elevation and manual updates.
Existing recovery mechanisms and protocol compatibility were preserved.
This is a code review and automated verification record, not a guarantee for
all hardware configurations.

The [published 0.1.17 workflow](https://github.com/aesgalexis/mouse-without-borders/actions/runs/41634161627)

assertions still require a fresh CI run in its disposable account.

## Changes made

- Added the MIT license selected by the owner, with license inclusion in future
  installer and portable packages. No acceptance dialog was added.
- Prepared `aesgalexis.MouseWithOutBorders` manifests for the existing public
  0.1.17 installer and a generator that verifies published bytes before emitting
  metadata. The manifests preserve the current Inno AppId, publisher and user scope.
- Removed the tag publication path that could overwrite published release assets.
  Both main and version tags now create releases without replacing existing ones.
- Added disposable installer checks for package detection, silent uninstall,
  bundled license, no silent-install launch and removal of uninstall registration.
- Corrected stale installation/testing text about optional clipboard sharing and
  replaced the old 0.1.1 CI checklist with version-specific evidence.

## Limits and remaining work

- Local full UI, native pointer/keyboard and installer execution were not run
  alongside the working app. Those checks install hooks, bind the production
  port or change per-user installation state. Use disposable Windows for them.
- The local transport and clipboard-service tests needed loopback access outside
  the sandbox. The same suites passed there. Symlink/junction clipboard cases
  were skipped because Windows did not grant creation privileges.
- The initial offline build reported NU1900 because vulnerability data could not
  be fetched. Final online restore and self-contained publish completed without
  warnings; no separate comprehensive security audit is claimed.
- Inno 6.7.3 warns that the existing `x64` architecture name is deprecated and
  substitutes `x64os`. Compilation succeeds; architecture settings were preserved.
- .NET 8 support ends on **2026-11-10**. Plan a separate migration and regression
  cycle on a supported LTS runtime before sustained broad distribution. Since
  these packages are self-contained, their embedded runtime needs a new release
  to receive updates. [Microsoft support policy](https://dotnet.microsoft.com/en-us/platform/support/policy).
- Publish the license and packaging changes before relying on the public
  LicenseUrl. Use a new release version to distribute the new license-bearing
  packages; do not replace existing 0.1.17 assets. Complete WinGet installation,
  detection, upgrade and uninstall checks in disposable Windows before submission.

No release or WinGet pull request was published by this review. The existing
0.1.17 manifest is a validated review candidate, while local rebuilt 0.1.17
packages are only compilation artifacts and have different hashes. Follow
[WINGET.md](WINGET.md) for the submission procedure.

## Publication follow-up

Following the owner's authorization, version 0.1.18 was published with .NET 10 LTS
and the bundled MIT license. No production `.cs` application logic changed.
The [release workflow](https://github.com/aesgalexis/mouse-without-borders/actions/runs/42048252576)
passed application, native clipboard, UI, build, packaging and native installer
installation/upgrade/uninstall checks. The additional local-manifest WinGet
harness and its security-policy/dialog automation were removed from the final tree.

The public installer was downloaded and verified against release checksums and
the GitHub asset digest. Its three manifests passed `winget validate` and were
submitted as [WinGet PR #471495](https://github.com/microsoft/winget-pkgs/pull/471495).
Community acceptance, its installation/security checks and catalog availability
remain pending. No successful local-manifest WinGet installation or new physical
two-PC acceptance is claimed. The working local installation was not changed.
